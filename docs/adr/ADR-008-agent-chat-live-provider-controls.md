# ADR-008: 单人 Agent 对话、课堂 Live 与 Provider 控制

Status: ACCEPTED — 2026-09-22 用户批准文字单聊、五能力管理入口、学生 Live 与登录页外的 Apple 风格 UI；实时语音最后实施，课堂 TTS 配置保持不动。

## 目标与边界

把需求合并为三项：老师/学生与一个已有 Agent 进行文字、语音、3D 对话；
老师在网页管理五个能力的 Real/Mock 与 Check；学生观看老师 Immerse 的同步内容。
操作键与发言记录拆开：按键固定在屏幕最右侧，无背景板；Transcript 打开记录侧栏。
不增加屏幕投射，不替换现有账号、Agent 发布、RAG、课堂状态机或费用记录系统。

“五个模型”在当前代码中实际是五个能力：Debate LLM、Embedding、Maya Report、
TTS、Voice。Voice 是声音克隆，不是语音识别；语音输入需要新增 ASR 能力。

## 1. 单人对话：共用页面，两种身份入口

老师、学生导航各增加 Chat。先选择已发布 Agent，再进入单人 3D + 消息列表 + 输入区。
首版可选择本课程全部当前已发布 Agent；跨课程、草稿和别人的私有声音不可用。

- 会话绑定用户、课程、不可变 AgentVersion 和 KnowledgeSnapshot；发布新版不会
  悄悄改变旧会话。换 Agent 开新会话，自己的历史可恢复，默认不让其他学生或老师
  自动读取个人会话内容。
- 复用 Persona、自己的知识检索、来源查看与平台 LLM 适配器；另建 chat session/
  message 存储和请求额度，不伪装成 Debate，也不回写 Agent.md。
- `/agent-versions/{version_id}/chat` 保留为草稿检索测试；新 Chat 使用独立的课程
  Agent 投影和会话接口，不扩大原有老师列表接口的权限。
- 实现复用了现有 React、ReportMarkdown、AvatarPreview、认证、Persona、不可变
  Snapshot 检索和 Provider 账本。没有引入 assistant-ui：首版不需要其分叉、工具
  执行或云历史功能，薄界面更小。服务器是历史、引用和费用的权威；网络失败后
  显式再次发送沿用请求 ID，不自动重新调用模型。未知接收结果终止该会话。
- 每会话最多 20 次发送，每用户每天最多 100 次；消息最多 4000 字符，历史达到
  出站预算时拒绝发送，不静默裁剪。Mock 明确标识并不联网。个人对话只本人可读，
  包括老师也不能直接读其他人的会话。退出课程后撤销访问。
- 语音按用户最新决定留到后续实时面对面对话阶段；不先增加按键录音或浏览器代转写。
  目标和复用边界见下文，不把当前文字与 3D 预览当作实时语音完成。

## 2. 五能力开关与单一 Check

由老师管理；学生不能看或改 API key。界面区分“选择 Real”和“已验证可用”，
不把保存成功当连接成功。缺 key 弹窗填写；提交后服务器只返回配置是否存在和检查状态，
不回传 key，不放 localStorage，不进入日志。持久密钥由服务器加密保存，主密钥不与
密文同库存储；不通过网页直接改 `.env`，也不默认给网页任意 URL 的 Provider 代理。

- 仅一个右上角 **Check**，先读最新配置，跳过 Ready 和 Deferred 项；真实检测先
  明确本批最多请求数，确认后用公开输入、独立额度和幂等键逐项检查，首个失败即停止。
  全部 Ready 时只读状态，零供应商调用；超时结果不明时不自动重试。
- 检查与配置修订号绑定；改模式仅使该项失效，改 key 使全部检查失效。五项独立展示，不能一个
  LLM 返回成功就声称 Voice、TTS、Embedding、Report 全部可用。
- 后续 Voice Check 应查询已有授权声音状态，不每次新建克隆；创建克隆和试听合成
  是独立、可计费、需授权的操作。当前 Voice/TTS 均为 Deferred。
- Real/Mock 切换作用于新任务；已运行任务冻结原配置，旧发言/报告/音频显示其原始
  来源。尤其不能用新 Embedding 空间查询旧向量；切换后不兼容快照必须重建或明确
  暂不可用，不能静默混用。
- 本地 Demo 持久化后热切换，不要求每次重启 Docker；检查修订号和后台活动状态。

当前实现限定单课程本地 Demo：LLM、Embedding、Report 可改；TTS 和依赖声音链路
的 Voice 显示 Deferred 且不可切换，不宣称已打通。Key 使用 AES-GCM 加密保存在
数据库，密钥由服务器 Session secret 分用途派生，API 仅返回 credential_ready。
切换检查修订号，活跃生成/课堂/聊天/预热期间拒绝切换；重启恢复保存的配置。
Embedding Check 必须使用真实索引，不能把 Mock 检索误报成真实服务可用。
LLM/Report Check 验证同一已配置模型的公开 JSON 请求，不代表完整 Report 质量验收。

## 3. 为什么 TTS/Voice 仍是 Mock

审查时运行中的 LLM/Embedding/Report 为真实适配器，TTS/Voice 为 Mock。
以下是代码限制，不只是少填一个 key：

1. `backend/app/core/config.py` 明确拒绝运行时 Real Voice；允许的多真实组合没有
   TTS + LLM + Embedding + Report。
2. `backend/app/providers/factory.py` 和 `dashscope.py` 已有真实 TTS/克隆适配器，
   应复用，但仍需校验当前供应商接口、响应、声音授权、策略和计费规则。TTS 方法的
   language 参数目前没有发给供应商，中文/英文质量需要实测，不能仅凭方法签名认定支持。

Composition 已改为读取实际配置，不再写死 Mock 标签；这不启用或验证语音服务。

后续打通真实 TTS 时使用允许的系统音色或完成准备/试听确认的默认声音；
后者若依赖克隆，要按现有分阶段流程办理，不能凭空使用 Mock voice id。
再接个人授权声音克隆，保持上传者所有权；“可选择某个 Agent”不等于“可用作者私有声音”。
最后接 ASR。扩大组合时同时补政策、成本上限、DTO、测试与故障处理，不移除安全门禁。
旧 Mock WAV 不会随配置变成真语音，只有对指定内容重新合成后才能验收为真实。

## 4. 学生 Live：共享课堂状态，不共享老师屏幕

直接扩展 `backend/app/modules/debates/playback/` 已有快照与有序事件，以及当前 Three.js
舞台；不新增媒体服务器。现有事件路由按老师授权，不能直接让学生使用控制员连接。

- 老师成功进入 Immerse 并持有有效控制权时，显式建立 Live 会话；不是链接预取或 GET
  请求就开直播。同课程学生的 Live 按钮亮起，并有文字状态，不只依赖颜色。
- 学生连接独立只读订阅，获得参与者、已公开发言、当前轮次、音频资源和播放游标。
  老师 Next/暂停/结束同步；不暴露私有教师备注、未发布内容、控制 token 或供应商 URL。
- 同一条音频由各设备播放，时间戳/游标校正误差；目标是相同内容和近实时进度，不承诺
  像素级画面一致。学生首次点击 Live 处理音频播放授权，拒绝/失败仍能看文字。
- 中途加入或重新进入先收当前快照，再按 sequence 消费事件，忽略旧消息；不自动重连。
  舞台下方列出完整公开发言记录，按新发言滚动；没有 Refresh 行。
- 老师退出/End 关闭直播；断网或关页面由服务端租约到期关灯；控制权转移要有会话版本，
  防止旧老师页面重新发布。学生永远不能推进课堂。
- Live 只播放已生成内容，不给每个学生重复调用模型或 TTS。媒体使用独立学生路由，
  每次读取验证登录 Session、课程成员关系、有效 Live 租约、公开 turn 和保留音频
  哈希，不复用老师的媒体 ticket；响应 private/no-store。

## 顺序与验收

按用户最新决定，先完成“文字单聊 + 3D → 五能力入口 → 学生 Live → 全部非登录 UI”，
统一验收、同步和重启后交用户人工审计；实时语音之后做。
不以开源 Demo 能启动代替 Maya 集成验收。

| 功能          | 必须证明                                                                                                                                |
| ------------- | --------------------------------------------------------------------------------------------------------------------------------------- |
| 单聊          | 老师/学生都能选授权 Agent、多轮上下文与重新进入恢复；跨用户/课程访问被拒绝；引用归属正确；不接入第三方聊天托管。                        |
| 语音/3D       | 中英文真实转写和朗读；麦克风拒绝、TTS 失败仍可文字交流；重复点击不重复计费；停止音频立即停止嘴部动画；学生 HTTPS 实机测试。             |
| Provider 控制 | 缺 key、错误 key、额度不足、检查过期、配置竞争均有状态；全部 Ready 时 Check 零调用；真实检测独立记录；切换不污染旧产物。                |
| Live          | 两个身份同时在线；入场、Next、中途加入、断线手动恢复、老师退出/租约过期均同步；学生无法发控制命令或读未公开内容；多学生不增加生成调用。 |

全双工通话、精确音素口型、新的人物资产、多供应商网关与课堂规模压测不算首版已交付。

## 实时语音的后续边界

用户选择百炼北京，并授权有限真实测试。目标是面对 3D 人物连续说话、AI 直接语音
回答，可插话而非先转文字再点 Send；默认不开摄像头。现有文本 Key 是否有 Omni
Realtime 权限需单独检查，不能由文本请求成功推断。语音工作已按用户要求暂停。
已审查阿里官方 [speech-demo](https://github.com/aliyun/alibabacloud-bailian-speech-demo/tree/1082942345c555429ee61c04b8c585f12e06dab2)
（MIT）的 Omni server-VAD 示例与依赖：使用 DashScope SDK，桌面示例依赖 PyAudio，
不能原样放入现有网页。后续审计其浏览器示例及官方 WebRTC 路线，复用采集/播放与
协议代码，补 Maya 权限、人设、费用和隐私边界，不搬整套无关应用。未引入依赖、
未调用实时模型，也不改变现有课堂 TTS。

## UI 与代码约束

使用 ui-ux-pro-max 的可访问性、响应式和一致性原则；系统字体、灰白表面、登录页
暖黄色与深棕文字、轻量圆角和紧凑分组。原版金环 Logo 替换 Mayaform 导航项的 Home
图标，不另设品牌栏。主页面去掉可见总标题和副标题，保留读屏标题与模块标题，操作
随模块对齐。Components 为紧凑五列，只有一个 Check；Chat 不重复人名；Accounts 仅
展示账号名、组名和状态，保留管理操作。Immerse 固定大小的按键在右侧独立排列，无
背景板；Transcript 切换记录栏，保留 Public Debate、状态、进度与 Check RAG。
所有 Refresh 按钮及列表批量重试入口移除，状态读取和明确的授权/生成动作仍分开。
New / Back / Done 统一在侧栏，与导航对齐；不可用时隐藏。各页注册原有动作，主内容区
不重复放创建、返回或提交按钮；全屏 Immerse、文件选择和安全确认弹窗保留独立控制。
Chat 只有 New / Send，不加 Back、Done、effort 或上传。Agent 直接展示当前版本；此处
New 创建下一版或打开已有草稿。学生编辑器 Done 表示发布，先保存最新修改，再检查
服务器返回的阻塞项；Compile 也先保存，Persona 确认、知识、权限和费用门槛不变。
Workspace 不再重复知识库；知识/声音表单按需展开，Back 关闭，Done 提交。
登录/注册样式隔离，不换角色资产或用户业务内容。
最新要求允许删解释性文案并缩短按钮；必要权限、费用、数据删除和错误信息保留。
最少代码解决明确需求，不增加单次使用的抽象，具体规范归 AGENTS.md。
