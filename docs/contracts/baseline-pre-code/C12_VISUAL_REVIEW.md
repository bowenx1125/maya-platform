## 1. 参考项目的正确分工

### OpenMAIC：主要视觉参考

用于课堂与 AI 教学的核心视觉语言：

- 深色互动舞台与聚焦中的发言者；
- 同屏角色、发言气泡、准备/播放状态和控制 Dock；
- RAG/来源等教学因果的显式标签；
- 辩论、互动和报告在同一课堂画布中的阶段切换；
- 靛紫色主交互、金色 Live/发言状态和轻量玻璃层次；
- OpenMAIC 的柔和课堂工具感与清晰信息层级；具体字体不照搬，Maya 使用 V2 柔和无衬线视觉语言。

不采用其课程生成、课件、白板、Provider 选择、复杂左右栏和巨型组件，也不复制任何实现代码。

### RomanticSimulation：辅助视觉参考

只用于后台和制作页面的信息组织：

- 温暖浅底、安静留白和低压力表单；
- 编辑任务的卡片/分区层级；
- 桌面多栏到手机单栏的自然重排；
- 角色列表、状态摘要和历史页面的可读性。

不采用恋爱产品的粉橙主色、生活化叙事、过大的宣传型标题、领域文案或关系图业务。

- 后台/制作端：暖象牙白底色 + 靛紫主操作 + 少量金色教学提示；全站字体、标题、字号、字重、字距和行距以 Visual Draft V2 为冻结基线，使用 `Inter Variable/Inter/PingFang SC/Noto Sans SC` 柔和无衬线栈与紧凑层级；Georgia 和 Times 均不使用；

- 学生端强调“构建步骤和教学因果”，教师端强调“已发布成果、顺序和课堂控制”，观众端只强调两项独立提交；
- 参考项目只提供视觉原则，页面、组件、领域对象和代码全部按 Maya 合同独立设计。

- 用户接受平台气质、浅色后台/深色课堂、暖象牙白+靛紫+金色、学生构建层级和手机独立提交；
- 教师页保留 V2 增加的顶部规则胶囊和固定流程条，顺序标识使用 V2 原始 A-E；

- 课堂互动改为左侧二维码、中间大面积 `RAW BARRAGE`、右侧 `LIVE VOTE`；弹幕按全部原始提交自动慢速纵向滚动，悬停暂停，系统“减少动态效果”设置下改为手动滚动；

## 5. 已冻结的审阅结论

1. 整体定位为“文明互鉴的 AI 教学平台”，不是恋爱产品、游戏或企业管理后台；
2. 接受“后台浅色、课堂大屏深色”的双场景设计；
3. 接受暖象牙白 + 靛紫 + 金色；字体、标题、字号、字重、字距和行距按 V2 柔和无衬线基线，Georgia/Times 不使用；
4. 学生端清楚区分 AGENT.md、RAG、3D、音色和发布检查；
5. 教师从 `A. Bowen Agent / B. KaiKai Agent`、顶部规则胶囊和流程条理解 A-E 顺序、固定两轮、立场和 Maya 固定存在；
6. 大屏不写 speaking/listening 状态文字，只使用发言高亮、波形和聆听动作；真实课堂清晰度留到 3D 实机验收；
7. 接受 2/3/5 人同排布局和人数越多头脸越小的策略；正式 3D 尖刺仍需验证性能；
8. 互动阶段位置固定为“二维码 / 中间滚动原始弹幕 / 右侧匿名票数”；
9. 手机页清楚表达投票和弹幕互不关联、一项成功不锁另一项；
10. 中英文切换后，按钮和重要状态仍需在真实产品文案中做回归，但不再重新讨论全局视觉方向。

## 7. 当前风险

- 5 个真实 3D 头脸的 GPU、Blendshape 和 TTS 同步性能尚未验证；视觉排布通过不等于渲染通过；
- Visual Draft 使用抽象头像占位，真实 GLB 的发型、头肩比例和材质可能改变舞台留白；
- OpenMAIC 的信息密度若继续照搬会挤压 3D 主舞台；实现必须只保留 Maya 需要的状态和控制；
- RomanticSimulation 的生活化叙事和粉橙暖色若使用过量，会让产品偏向生活方式产品；冻结基线只允许它影响后台留白/卡片，不影响课堂业务语言；
- 视觉稿继续迭代的新增风险高于收益；Visual Draft V2 现已冻结为 Demo 终稿，以后只修真实可读性、溢出、无障碍缺陷或用户明确重新打开的问题；
- 纯动作表达比文字更干净，但真实 3D 若高亮不够强、聆听动作太细，后排观众可能看不懂当前状态；实现时必须用投影距离复测发言光环、头像对比和动作幅度；
- 原始弹幕持续滚动可能降低长文本可读性；V2 采用慢速、边缘渐隐、悬停暂停和减少动态效果降级，真实课堂还需根据投影与平均弹幕长度调速；
- 大屏证据面板在 1280×720 可并排，普通笔记本窄屏会下移；最终课堂验收必须以教师目标电脑和投影分辨率为准；
- 中英文长度差异仍需在真实组件和真实错误消息中验证；视觉稿只能证明主要文案层级。
